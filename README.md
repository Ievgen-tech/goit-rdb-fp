# goit-rdb-fp
# Фінальний проєкт: Реляційні бази даних (GoIT)

Цей репозиторій містить рішення фінального проєкту з модуля "Реляційні бази даних" (RDB). Проєкт демонструє повний цикл роботи з даними: від створення бази даних та імпорту сирих даних до їх нормалізації, аналізу та написання користувацьких функцій. Увесь код оптимізовано для поетапного безпомилкового виконання (без "жовтих" попереджень).

##  Технології та інструменти
* **СУБД:** MySQL
* **Інструмент:** MySQL Workbench
* **Мова запитів:** SQL (DDL, DML, DQL)

##  Структура проєкту
* `final_project.sql` - єдиний SQL-скрипт, що містить код для всіх 5 завдань.
* `infectious_cases.csv` - початковий датасет (наданий платформою).
* Папка зі скриншотами, які підтверджують успішне виконання кожного етапу:
  * `p1_import.png` - створена схема та імпорт даних.
  * `p2_normalization.png` - результат нормалізації та запиту COUNT.
  * `p3_analysis.png` - аналіз даних (агрегатні функції).
  * `p4_count_dates.png` - розрахунок різниці в роках (вбудовані функції).
  * `p5_function.png` - результат роботи власної функції.

##  Опис завдань

### Завдання 1: Створення бази даних
Створено нову схему `pandemic` та зроблено її активною (`USE pandemic`). Сирі дані імпортовані з файлу `infectious_cases.csv` за допомогою *Table Data Import Wizard*.

### Завдання 2: Нормалізація даних (3НФ)
Початкова таблиця містила дублювання тексту (назви країн та їх коди). Дані були нормалізовані до Третьої нормальної форми (3НФ):
1. Створено таблицю-довідник `countries` (з полями `id`, `entity`, `code`).
2. Створено головну таблицю `infectious_cases_norm`, яка пов'язана з довідником через зовнішній ключ (`FOREIGN KEY`).
3. Дані успішно перенесені без втрат, текстові значення замінені на відповідні `country_id`.
*Примітка: для обробки порожніх значень та очищення даних від невидимих пробілів після імпорту CSV-файлу використано комбінацію `NULLIF(TRIM(...), '')`. Стовпці з медичними показниками переведено у формат `DOUBLE`.*

### Завдання 3: Аналіз даних
Написано запит для аналізу випадків сказу (`number_rabies`). З використанням `JOIN` та агрегатних функцій виведено:
* Середнє (`AVG`), мінімальне (`MIN`), максимальне (`MAX`) значення та суму (`SUM`).
* Дані згруповано за країнами (`GROUP BY`) та відсортовано за середнім значенням за спаданням (`ORDER BY ... DESC`). Виведено топ-10 записів.

### Завдання 4: Робота з датами
Продемонстровано роботу з вбудованими функціями дат:
* Зі стовпця `year` сформовано дату 1 січня відповідного року (`MAKEDATE`).
* Отримано поточну дату (`CURDATE`).
* Вирахувано різницю в роках між цими датами за допомогою `TIMESTAMPDIFF`.

### Завдання 5: Створення власної функції
Створено користувацьку функцію `calculate_years_diff`, яка:
* Приймає на вхід рік (`INT`).
* Повертає різницю в роках між заданим роком та поточним часом.
* Має захист від порожніх значень (повертає `NULL`, якщо на вхід передано `NULL`).
Продемонстровано виклик функції у запиті `SELECT`.

##  Інструкція із запуску коду

Для коректного виконання скрипту та отримання ідеально "зелених" логів без попереджень, виконуйте код **покроково**, виділяючи відповідні блоки мишкою:

1. **Крок 1 (Створення схеми):** Виділіть перші рядки (`DROP SCHEMA... CREATE SCHEMA... USE pandemic;`) та виконайте їх через опцію "Execute the selected portion" (іконка блискавки з курсором).
2. **Крок 2 (Ручний імпорт):** Зробіть імпорт файлу `infectious_cases.csv` у створену базу `pandemic` через *Table Data Import Wizard* у MySQL Workbench. Дочекайтеся завершення імпорту.
3. **Крок 3 (Виконання завдань):** Почергово виділяйте код кожного наступного завдання (Завдання 2, 3, 4, 5) від заголовка до заголовка та виконуйте їх окремо згори донизу.
